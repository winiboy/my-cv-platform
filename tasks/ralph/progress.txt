FINDINGS REGISTER (AC-4)

D-1 fontFamily - REFUTED. FONTS[4].family is byte-identical to the literals in
  the wrapper and the DOCX route. Consolidated; pinned by a named test.

D-2 the three slider copies - CONFIRMED IDENTICAL. All 14 numeric values agree
  across resume-preview-wrapper.tsx, resume-editor.tsx and
  download-docx/route.ts. Resolution: one constant.

D-3 Preview vs DOCX title size - CONFIRMED. REPORTED, NOT FIXED.
  The wrapper seeds titleFontSize = 24 for EVERY template and always passes it,
  so each template component's own prop default is dead code in the app path:
      professional  Preview 22  DOCX 22  (consistent; accepts no prop)
      modern        Preview 24  DOCX 36
      classic       Preview 24  DOCX 36
      minimal       Preview 24  DOCX 48
      creative      Preview 24  DOCX 48
  Four templates diverge, not one. Resolution: reported. Fixing it changes
  Preview or DOCX pixels, which FR-6, AC-5 and the PRD FAIL condition forbid in
  this part. Needs its own approved story.

D-4 seven slider properties never reach DOCX - CONFIRMED. REPORTED, NOT FIXED.
  DocxGeneratorSettings carries no titleFontSize, titleGap, contactFontSize,
  sectionTitleFontSize, sectionDescFontSize, sectionGap or headerGap, and the
  download buttons never send them. The generators' per-template FONT_SIZES are
  hardcoded stand-ins. This is the mechanism behind D-3.

D-5 DEFAULT_SIDEBAR_ORDER declared twice - NOT A DIVERGENCE. resume-editor.tsx
  used the editor vocabulary; docx-modern.ts uses the Modern-template
  vocabulary. Two legitimate domains, bridged by mapEditorOrderToModern. The
  editor's copy now consumes the shared default; docx-modern's stays as
  template identity. Its copy is in fact unreachable, since
  mapEditorOrderToModern always returns a non-empty array - dead, but removing
  it is unrelated cleanup.

D-6 professional-template hardcodes TITLE_GAP=8, SECTION_GAP=12, HEADER_GAP=12
  and ignores the gap sliders; HEADER_GAP is unused. REPORTED, NOT FIXED.
  Values happen to equal the shared defaults. Wiring fixed template spacing to
  a slider the template does not honour would create a false dependency and put
  template isolation (FR-7) at risk.

D-7 titleGap, sectionGap and headerGap have NO producing control anywhere.
  REPORTED, NOT FIXED. resume-preview.tsx declares setTitleGap, setSectionGap
  and setHeaderGap as props and never forwards them to any template. Dead-end
  props, pre-existing. Their LAYOUT_CONTROL_RANGES entries are null with the
  reason recorded. Same class as the US-001 finding about 8 professional
  print:hidden sites gated on props the wrapper never passes.

D-8 mainContentTopMargin lower bound rejected reachable user state.
  INTRODUCED BY THIS STORY. FIXED.
  The first implementation assumed a zero floor for every margin. The
  main-content drag handle clamps to Math.max(-20, ...) in
  professional-template.tsx:168, and setMainContentTopMargin is wired live in
  resume-preview.tsx and resume-editor.tsx, both persisting to
  resume_slider_settings_*. Every value from -20 to -1 was dropped by
  parseLayoutModel and refilled with the default 24 - a silent 44px jump on
  reload, with no user action, breaching the PRD FAIL condition on output
  change. Found by code-reviewer pass 1, not by the implementation.
  Resolution: LAYOUT_CONTROL_RANGES now records what each control can actually
  emit, each entry citing the clamp it mirrors, and NUMERIC_RANGES widens
  outward from those rather than from assumed floors. mainContentTopMargin is
  [-200, 500]. Out-of-range values are still dropped, never clamped - clamping
  would itself be an output change. Boundary tests were verified to FAIL
  against the old bound before the bound was fixed.

D-9 editor typography edits are never persisted. PRE-EXISTING. REPORTED, NOT
  FIXED. The editor holds all seven typography keys as state, loads them, and
  forwards the four font sizes to Classic, Minimal and Creative, where each
  renders as a live slider - but its save effect's dependency list omits all
  seven, so an in-editor font-size change is never written, and the next
  unrelated save writes the stored value back over it. This is why the
  serializer is seeded from the stored blob rather than from editor state:
  seeding from state would newly persist typography edits, a behaviour change
  out of scope here.

D-10 Modern accepts four font-size props and attaches no control to any.
  PRE-EXISTING. REPORTED, NOT FIXED. modern-template.tsx has zero range inputs.
  It destructures setTitleFontSize, setSectionTitleFontSize and
  setSectionDescFontSize and never calls them; it styles text with only
  titleFontSize and sectionDescFontSize; sectionTitleFontSize is destructured
  but never read; contactFontSize is declared as a prop type and never
  destructured at all, while resume-preview.tsx forwards it. Same dead-end-prop
  class as D-7. Found because two successive attempts to describe this in a
  comment - the orchestrator's and the reviewer's proposed correction - were
  both factually wrong; the third was written from the code.

Deliberate behaviour change, malformed input only:
- Validation now runs before layout state reaches rendering (FR-5).
  titleFontSize: "abc" previously produced fontSize: "abcpx"; it now falls back

- Persisted-format change: both writers now emit the model's fixed key order,

  only readers of resume_slider_settings_* are the editor, the wrapper and the

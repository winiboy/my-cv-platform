Decision (owner, chat, 2026-11-05, answering the orchestrator's questions):
- "Repli automatique sur le CV."
  - A letter whose phone, e-mail or locality is null takes the linked CV's value, in the editor now and in the preview, PDF and Word later. All of them go through `effectiveSenderDetails`, with the server loading the linked CV's contact filtered by its owner.
  - Opening such a letter does not mark it unsaved; the values are stored on the next real save.
  - A field the user clears is stored as "" and is not refilled.
  - This replaces the PRD's US-001 wording "On a letter whose sender fields are all empty": the fallback works field by field.
- "Contrôle dans l'éditeur + dette notée."
  - The editor validates the five fields with the API's zod shape before its direct RLS write.
  - **Debt:** the editor's save still writes directly through the Supabase client, not through PATCH, for every cover-letter field. A later PRD should move it to the API so validation is server-side on every path (`CLAUDE.md` §12–13).
- No CHECK constraints in migration 010; no other text column of this table has one. The limits are in the APIs and the editor.

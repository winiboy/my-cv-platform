Scope:

- Changed paths: story diff sha256 prefix 0237c953b9e67c40. The hash covers `git diff -- src e2e`, then "== <path>" and the content of each new file.
  - **New `src/lib/cover-letter-page-breaks.ts`:** `computeCoverLetterPageBreaks({ lines, contentBottom })`, pure and server-safe (it imports only `cover-letter-swiss-letter`), shared by both previews and by US-002 (FR-1).
    - It reproduces Chromium's print fragmentation. Each line is `{ top, bottom, block }` in unscaled preview px.
    - Page 1 ends at 1066 px; each later page holds 998 px. Chromium prints the A4 page as 1123 px with each `@page` margin rounded to a whole px (15 mm → 57, 18 mm → 68). This was established by bisecting page counts with the server's own `page.pdf({ preferCSSPageSize: true })` call and is documented in the file (`printedMarginPx`).
    - A line whose bottom passes the page end moves to the next page. Orphans and widows are 2 within the overflowing line's block, as Chromium's defaults; nothing on the letter's print path sets `orphans`, `widows` or `break-*`.
    - Each boundary is the top of the first line moved to the next page. With no lines, `contentBottom` breaks at each page end with a 1 px tolerance, so a letter at the template's minimum height is one page.
  - **New `src/components/dashboard/cover-letter-line-boxes.ts`:** reads the rendered sheet's line boxes, in unscaled px.
    - Text uses the browser's client rects. A `<br>`-only or `&nbsp;`-only line is a full line box.
    - Each piece of text gets a box one line-height tall, `floor((line-height − glyph height) / 2)` above its glyphs (negative for a font taller than the line height), unioned with the paragraph's strut on the same baseline. Font metrics come from a detached canvas.
  - **New `src/components/dashboard/cover-letter-page-break-markers.tsx`:** the marker overlay.
    - It uses the CV marker's look and test ids: a dashed teal/70 % line and a vertical 10 px "Page N" label 3 px right of the sheet. It is `aria-hidden`, `pointer-events-none`, `select-none` and `print:hidden`.
    - The line is a 1 px dashed border, counter-scaled, so it is 1.000 px on screen at every zoom.
    - A label is drawn only when the gutter inside the scroll area is at least 16 px. Otherwise only the line is drawn.
  - **`src/components/dashboard/cover-letter-preview.tsx`:** renders the markers next to the sheet inside the scaled wrapper. It re-measures the lines on resize, DOM mutation and font load, at most once per frame. The zoom code is unchanged.
  - **`src/locales/{fr,en,de,it}/common.json`:** `coverLetters.editor.pageBreakLabel`: "Page {page}", "Page {page}", "Seite {page}", "Pagina {page}".

Decision:
- **Lines, not height.** The shared computation takes line boxes, so it can reproduce how Chromium moves a whole line, and orphans and widows, to the next page. A height-only formula put the second marker of a 3-page letter 7 px low.
- **The PDF anchors the test.** The e2e reads each expected break from the downloaded PDF's baselines, calibrated on page 1, not from the same line model the code uses.
- **Whole-px page edges.** The page constants come from Chromium's printed page (1123 px, margins rounded to whole px), not from mm, after the PDF-anchored test showed the mm values put markers one line early.

Open owner decisions:
- **Dark mode (follow-up, not this story):** with `.dark` forced, the label has about 2.2:1 contrast on the dark gutter. The CV marker uses the same colours, and nothing in the app sets the dark class today. The fix is `dark:text-teal-400` on both markers in one change.
- **CV editor line (separate issue):** the CV editor's marker line renders 0.942 px for a computed 2 px border, because of pixel rounding. The letter's marker avoids this.
- Minor code-review points left as they are:
  - the page-edge rule was measured on the local Playwright Chromium, while production renders with `@sparticuz/chromium`;
  - canvas font metrics may be fractional where Blink rounds them;
  - Firefox before 116 lacks `fontBoundingBoxAscent`, so no markers are drawn there;
  - a new canvas on every measurement;
  - a stale "1065.83" comment in the e2e;
  - an English fallback for the label, following the existing `zoomLabels` pattern.
- **US-002 note:** the server has no layout, so the one-page check will need line boxes from an estimate fed into the same function. Its accuracy is US-002's risk; the PDF stays the authority.

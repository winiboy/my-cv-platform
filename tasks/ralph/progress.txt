Decision:
- **Opt-in on the shared editor.** The letter's three fields enable the buttons, and the CV's fields stay byte-identical.
- **Narrow, don't widen.** The sanitizer keeps exactly the four values, which matches what the Word parser already accepted, so the preview, PDF and Word file agree on every stored value.
- **Verification layer.** The PRD asks for unit tests that set each value and align a multi-paragraph selection. jsdom has no `execCommand` or layout, and the sanitizer needs a DOM that vitest does not have. Those behaviours are therefore proven in Chromium by `e2e/cover-letter-paragraph-alignment.spec.ts` and `e2e/html-sanitizer.spec.ts`. The unit tests cover the mapping, the resolution and the rendered markup.

Open owner decisions:
- **Firefox is not verified.** Playwright's Firefox is not installed and every suite runs Chromium only. The scoped `styleWithCSS` should make Gecko write `text-align`, but this has not been observed.
- **Translation drops alignment.** `translate/letter-segments.ts` rebuilds the letter without attributes, so a translated copy is left-aligned. This is out of scope, as the PRD's Risks foresaw, and needs a follow-up.
- **Stored values outside the four.** A stored `end` or `-webkit-center` (no editor writes either) now renders left in previews and the CV/letter PDF. Parity and visual are unchanged.
- **Ribbon polish (ui-expert minors, existing traits):** dividers at the end of wrapped rows, 32 px buttons on mobile, and the focus ring only on the new buttons.
- Minor code-review points left as they are:
  - the undo test may pass without the `input` listener, because Chromium also fires `selectionchange`;
  - the sanitizer reads the first `text-align` and is case-sensitive on the property name, unlike the Word parser (this predates the story);
  - touch input is not exercised;
  - the group has no accessible name of its own, because no dictionary key fits.

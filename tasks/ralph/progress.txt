## US-001: The address comes from the offer's page
Status: PASS

Scope:
- Scope check: PASS
- Changed paths: story diff sha256 prefix 92c1a97914e119fb. The hash covers `git diff -- src e2e` (7 files, 651/26), then "== <path>" and the content of each of the three new files.
  - **New `src/lib/cover-letter-from-job/offer-page-address.ts`:** `companyAddressFromOfferPage(html)`.
    - It reads every `<script type="application/ld+json">` block, by a forward `indexOf` scan, with only ASCII A–Z lower-cased, so the positions match the original HTML.
    - It finds every `JobPosting`: a single node, an array or `@graph`, with `@type` as a string, a list, or a full name such as `https://schema.org/JobPosting`.
    - It takes the first complete `hiringOrganization.address` of any posting, then the first complete `jobLocation.address`.
    - Each part is cleaned with `sanitizeUntrustedPlainText` and capped at 249 characters, so 4 parts and 3 separators never go over 1,000.
    - Complete means a street, a postcode and a locality. A locality that repeats the postcode loses it, and one that is only the postcode is incomplete.
    - The country line is left out for CH, CHE, Switzerland, Suisse, Schweiz, Svizzera and Svizra.
    - An address containing U+FFFD (a wrong charset) is rejected.
  - **`src/lib/cover-letter-from-job/offer-availability.ts`:**
    - `answered` now carries `companyAddress: string | null`.
    - A 2xx `text/html` or `application/xhtml+xml` answer is read up to `OFFER_PAGE_MAX_BODY_BYTES` (1 MiB), in its declared charset (UTF-8 by default). The read uses whatever is left of the same 5 s `OFFER_PAGE_TIMEOUT_MS`. `safeFetch` clears its own timer once it returns the response, so every read is raced against the remaining time.
    - Any other answer, a read error or a timeout gives `answered` with a `null` address.
    - 404 and 410 still cancel the body without reading it.
    - The verdicts are unchanged.
  - **`src/app/api/cover-letters/from-job-application/route.ts`:** one line stores `company_address` from the same single page check, or `null`.
  - **`src/lib/ai/test-stub.ts`, `test-stub-contract.ts`:** `ai-test-stub-page-address=job-posting` makes a stubbed 200 page carry a fixed `JobPosting`. Its hiring organization is at Avenue de la Gare 10, 1003 Lausanne, CH, and its job location is elsewhere. The real parser reads it. The existing stub behaviour is unchanged.
  - **Tests:**
    - `offer-page-address.test.ts` (new): every fixture the PRD lists, plus İ before the block, a repeated postcode, full-name `@type`, U+FFFD and a linear-time scan.
    - `offer-availability.test.ts`:

      - a block cut by the cap is skipped;

Decision:
- **One fetch.** The address is read from the response the availability check already gets, so the page is never fetched twice (FR-3, AC-04).
- **A capped prefix, not nothing.** A page over 1 MiB is parsed up to the cap: boards put the JSON-LD in the head. A block the cap cuts in half fails to parse and is skipped.
- **When in doubt, no address.** A wrong charset (U+FFFD) or a postcode-only locality gives an empty field, never a damaged value.

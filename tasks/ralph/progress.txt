### US-001: Explore current drag-and-drop and section ordering data model
- Status: PASS
- Commit: (exploration only — no code changes)
- Priority: 1

#### Findings

**ROOT CAUSE:** Section order is stored in localStorage only — never saved to Supabase. The handleSave() function (resume-editor.tsx:419-457) does NOT include sidebarOrder or mainContentOrder. Database schema has no fields for section ordering.

**Current flow:**
- Editor drag-drop → React state → localStorage (resume_slider_settings_{id})
- Live Preview reads from localStorage (resume-preview-wrapper.tsx:54-93)
- DOCX export reads from localStorage via query params (download-button.tsx:26-99)
- PDF export uses Live Preview DOM (window.print)
- ALL work within a session, but order is LOST on Supabase reload (new device/cleared storage)

**Section IDs:**
- Editor sidebar: keyAchievements, skills, languages, training
- Editor main: summary, experience, education
- Modern template sidebar: contact, education, skills, languages, training
- Modern template main: summary, experience

**Section ID mismatch:** Editor and Modern template use different default section lists.

**Key files:**
- resume-editor.tsx: drag-drop (1204-1341), state (186-187), localStorage save (982-991), handleSave (419-457)
- modern-template.tsx: renders in order (953-955, 1007-1009), receives props (197-200)
- resume-preview-wrapper.tsx: loads from localStorage (54-93)
- download-button.tsx: reads localStorage for DOCX params (26-99)
- docx-modern.ts: accepts and uses section order (275-296)
- database.ts: NO section order fields exist

**Fix strategy:**
1. Add sidebarSectionOrder and mainSectionOrder to resume JSONB content
2. Update handleSave() to persist these fields to Supabase
3. Load from Supabase on mount (with localStorage as cache/fallback)
4. Modern template renderer already consumes order — just needs correct data flow

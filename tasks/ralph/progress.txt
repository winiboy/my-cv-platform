This story drops a function, unlike US-001 and US-002:
- FR-3 forbids deleting rows and dropping columns; it does not cover catalog
  objects, and criterion 1 in the same acceptance list mandates this drop.
  code-reviewer adjudicated the same reading independently.

The NOW() problem, and why the obvious check would have been worthless:
- The harness runs in ONE transaction, and NOW() returns transaction start
  time. A fixture inserted in that transaction already carries
  updated_at = NOW(), so the trigger writes the same value. Measured:
  'updated_at > previous' is FALSE with a working trigger; 'updated_at >=
  previous' is TRUE with no trigger at all. Neither records anything.
- The check instead supplies a sentinel the transaction clock can never equal
  and asserts the post-trigger image in a single data-modifying CTE:
    WITH bumped AS (UPDATE ... SET updated_at = '2000-01-01' ... RETURNING
    updated_at) SELECT 1 FROM bumped WHERE updated_at = now()
  One statement, not two: RETURNING yields the post-trigger row, so a row the
  update never matched cannot pass. code-reviewer re-derived this with five
  probes rather than accepting the argument, and confirmed the now() equality
  is guaranteed rather than incidental - both the trigger body and the outer
  SELECT resolve to transaction_timestamp().
- The check proves the narrower property "the trigger overwrites a
  caller-supplied updated_at with transaction time". Literal cross-transaction
  advancement would require committing, which the harness ROLLBACK contract
  forbids.

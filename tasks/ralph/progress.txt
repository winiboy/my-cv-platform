Review history:
- First pass FAIL, two critical findings, both proven by execution:
  * Criterion 3's check could not fail when the criterion was violated.
    PostgreSQL pre-filters a column-referencing DELETE through the SELECT
    policy, so 'DELETE ... WHERE id=<A's>' as B returns 0 regardless of the
    DELETE predicate. Under USING (true) an UNQUALIFIED delete as B destroys
    A's rows - criterion 3 false in reality while the harness reported PASS.
    Reproduced independently by the orchestrator before acting.
  * The cascade test deleted :R1, which cascades to :GL via
    cv_generation_logs.resume_id NOT NULL ON DELETE CASCADE - the only
    cv_generation_logs fixture. US-004's "verified by execution" criteria
    would have passed vacuously against rows that no longer existed.
- Fixed: added a role-scoped unqualified-delete check for B; seeded a private
  parent resume :R3 and re-parented :AN2 onto it so :R1 and :GL survive; added
  check 47 asserting :GL survival as a permanent property.
- Re-review PASS, no remaining findings.

Notes for US-003, US-004 and US-005:
- Standing check (from US-001 review): any criterion phrased "verified by
  execution" must be asserted by a check whose actor column reads A, B or
  anon. A 'db:' actor is the privileged runner and proves nothing about policy.
- Second standing check (from US-002 review): a criterion about what a user
  CANNOT do needs a statement shape that would actually succeed if the policy
  were wrong. A column-referencing DELETE is pre-filtered by the SELECT policy
  and cannot discriminate on its own.
- Check 13 encodes a fixture invariant: it expects 0 because B owns no

- :R1 and :GL are intact at the end of the run and are the stable tail
  baseline. :AN and :JA are consumed mid-run; :AN2 and :R3 are consumed by the
  cascade block. A story needing any of those must seed its own fixture.
- DEFERRED: the docs/engineering/rls-audit.md closure note for finding D2 is
  owned by US-005, which already carries a docs change. The PRD appends that
  verification line to every story mechanically; updating the document five
  times is churn. If US-005 is dropped - the PRD names it as the story to drop
  under time pressure - this note must be reassigned, not lost. It currently
